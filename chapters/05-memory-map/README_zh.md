# 05 — 显式地址图与译码

## 集成变更

把 ROM、SRAM 和寄存器端点接到同一 Wishbone 主总线，并定义明确的字节地址图。CPU 仿真开始前，地址检查器验证对齐、区域重叠和空洞。

| 区域 | 字节地址 | 容量 | 访问 |
| --- | ---: | ---: | --- |
| ROM | `0x00000000–0x00000fff` | 4 KiB | 取指和读取 |
| SRAM | `0x00010000–0x00010fff` | 4 KiB | 读写与栈 |
| 寄存器 | `0x20000000–0x20000fff` | 4 KiB | 探测和完成 |

CPU 通过 AXI-Lite 发出字节地址。LiteX 桥在 32 位 Wishbone 总线上提供字地址；例如 `0x00010ffc / 4 = 0x000043ff`。

## 运行与验收

```sh
PYTHONHASHSEED=0 python3 chapters/05-memory-map/run.py
```

正常固件检查 ROM 末字、SRAM 首末字和寄存器读回，然后写完成码。负例固件从 `0x30000000` 读取；CPU trap handler 必须报告 `mcause=5`（load access fault）和故障标记，不能报告正常完成。地址图单元检查必须拒绝故意重叠的区域。

证据写入 `results/05/` 和 `results/05-unmapped/`，包括声明的地址图、LiteX 生成的地址图、固件镜像、日志和波形。

## 译码约束

- 一笔请求必须命中且只命中一个地址区域；重叠属于构建错误。
- 空洞没有目标设备，不能映射到相邻设备或返回旧数据。
- 译码负责选择应答设备，不负责多主设备仲裁或访问权限。
- 端点用时序登记的 ACK，确保应答属于当前选中的事务。
