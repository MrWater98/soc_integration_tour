# 03 — 固件 ROM 启动

## 集成变更

把内嵌指令列表替换为本阶段汇编生成的 RV32 固件。构建产物包括 ELF、原始二进制、按字排列的 hex、固定深度的 ROM 初始化镜像及 SHA-256 文件。LiteX CPU 复位地址和集成 ROM 都从字节地址 `0x00000000` 开始。

| 区域 | 字节地址 | 容量 | 用途 |
| --- | ---: | ---: | --- |
| ROM | `0x00000000–0x000003ff` | 1 KiB | 复位与固件 |
| 完成端点 | `0x20000000–0x20000fff` | 4 KiB | 固件通过标记 |
| CSR | `0xf0000000–0xf000ffff` | 64 KiB | LiteX 控制/状态空间 |

端点使用时序登记的 ACK，使桥接响应与目标事务对齐，避免采到过期的读值。

## 运行与验收

```sh
PYTHONHASHSEED=0 python3 chapters/03-rom/run.py
```

仿真前会拒绝空镜像、过大镜像、未对齐复位地址和超出 ROM 的复位地址。CPU 仿真必须记录地址 0 的取指和固件完成值 `0x35`。生成产物位于 `results/03/`。

## 镜像与地址合同

- RISC-V 固件采用小端序。`program.bin` 按字节排列；`program.hex` 每行一个 32 位字；`rom_init.hex` 填满全部 256 个 ROM 字。
- 地址图使用字节地址。Wishbone 字地址等于对齐后的字节地址除以 4；完成端点字节地址 `0x20000000` 对应 Wishbone 地址 `0x08000000`。
- RTL 仿真前会将生成的 `memory_map.csv` 与固件地址合同进行比较。

镜像检查和 CPU 完成标记都通过后，ROM 阶段才算验收。
