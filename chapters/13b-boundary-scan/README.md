# 13B：从 JTAG 到引脚——亲手找到连线故障

## 这一章只增加一件事

上一章能访问内部寄存器。这一章把扫描寄存器接到输出和输入引脚，看看它怎样检查板上连线。我们用一个四路回环板模型，不需要真实板卡。

```text
                      芯片                       板上连接（仿真）
功能逻辑 1010 ----+ 
                 |  输出选择器 --> OUT[3:0] ======== IN[3:0]
测试输出锁存器 --+        ^                            |
                         | EXTEST 接管                 | Capture
                         |                            v
TDI --> 边界移位寄存器 [输出预装载 4 位 | 输入采样 4 位] --> TDO
                  |
                  +-- Update：写入测试输出锁存器
```

**引脚上输出什么，由输出选择器决定；JTAG 移位过程本身不会逐位改变输出。** 本例只有输出和输入，未实现双向 IO 的输出使能单元。真实边界链长度和位含义要查器件 BSDL；这里的四路、八位链与指令编码是教学选择。

## 先运行

```bash
python chapters/13b-boundary-scan/run.py
```

依赖 Python、Icarus Verilog。打开 `results/13b/pins.html`：拖动事件滑块，看 TCK/TMS/TDI/TDO、OUT 与 IN。`pins.csv` 记录实际 RTL 引脚；`pins.vcd` 可看完整波形；`REPORT.md` 展示驱动、采样和错误位。`rtl/` 保存所有必要 RTL。

## 实验一：先观察，别接管

SAMPLE（本例编码 4）让功能逻辑继续输出 `1010`，Capture 同时记录输出和输入。健康回环下读回 `0xaa`：高四位输出为 `a`，低四位输入也为 `a`。

这里还可在 SAMPLE 扫描时预装载测试输出：送入 `0x10`，Update 把高四位 `0001` 保存到测试锁存器。但此时引脚仍输出功能值 `1010`。

```text
SAMPLE 阶段：移入 0001 --> 测试锁存器准备好
                         功能逻辑仍控制 OUT=1010
```

本例合并了采样和预装载行为；真实器件的 SAMPLE/PRELOAD 编码与实现查器件资料。

## 实验二：接管输出，再读输入

选择 EXTEST（本例编码 5）以后，输出切换为预装载的 `0001`。之后发送完整边界数据并 Update，才更新引脚值。

```text
选择 EXTEST --> OUT 使用测试锁存器 --> 板上连接传到 IN
                                      |
下一次 Capture <----------------------+ 
随后 Shift：把输入采样读回电脑
```

注意先写输出、再重新 Capture 输入。写入这一轮读到的副本来自更新前，不能把它当成更新后的连线响应。

工具逐位驱动 `0001、0010、0100、1000`，再试 `1111、0000`。健康模型中输入等于输出；这些模式是本测试集选择，不是所有板卡的完整测试集。

## 实验三：一根线卡在 0

故障模型让 IN[1] 始终为零，相当于观察一根无法传递高电平的线：

| 驱动 OUT | 正常应读到 | 故障实际读到 | 错误位：两者异或 |
| --- | --- | --- | --- |
| `0001` | `0001` | `0001` | `0000` |
| `0010` | `0010` | `0000` | `0010` |
| `1111` | `1111` | `1101` | `0010` |

工具从真实 TDO 重建采样值，再与健康连线的期望比较，错误掩码指出 bit1。不需要 CPU 跑程序就能观察这个故障。这里断线以 stuck-low 数字模型近似；真实悬空电平依赖上拉、下拉和电气状态。

## 实验四：两根线短接

让 IN[0]、IN[1] 都读到 OUT[0] OR OUT[1]，用 wired-OR 数字模型演示：

```text
OUT=0001：正常 IN=0001，故障 IN=0011 --> bit1 意外跟着变高
OUT=0010：正常 IN=0010，故障 IN=0011 --> bit0 意外跟着变高
OUT=1111：正常 IN=1111，故障 IN=1111 --> 只试全 1 会漏掉这个错误
```

短接时真实驱动可能冲突；这个实验验证测试模式和检查方法，不预测电流、电压或损坏。数字故障只发生在模拟连线上，运行脚本不会驱动真实板卡。

## 实验五：退出测试，把引脚交回功能逻辑

重新选择 SAMPLE 后，OUT 恢复 `1010`。测试输出锁存器还在，但不再控制引脚。测试模式需要有清楚的进入和退出步骤。

运行器共做 21 项检查，包括 Shift 期间输出稳定、健康读回、故障出现与退出测试。故障场景 PASS 表示符合注入模型且检测到了相对健康连线的错误。

## 哪些是参数，哪些是本例固定实现？

| 项目 | 本例 | 修改影响 |
| --- | --- | --- |
| IO 数量 | RTL 固定 4 输出、4 输入 | 要一起改边界宽度、连线模型、测试与读回重组 |
| 边界扫描长度 | 当前 8 位 | 由实际边界单元布局决定，不由 JTAG 四线数量决定 |
| IR 长度 | 当前 4 位 | 要同步软件扫描长度 |
| SAMPLE / EXTEST | 教学编码 4 / 5 | 真实芯片必须查文档/BSDL |
| 功能输出 | 教学固定 `0xa` | 可替换为系统逻辑，测试时仍通过选择器接管 |

## 代码怎么对应图？

`tap.sv` 中 `boundary_shift` 用于串行传输；`boundary_drive` 保存已经提交的输出值；`pin_out` 的选择器决定使用功能输出还是测试输出。`pin_bridge.sv` 模拟四根板上连线与故障，`pin_driver.py` 只设置引脚电平并记录响应，`run.py` 检查扫描读回。

IEEE 的边界扫描目标见 [IEEE 工作组说明](https://grouper.ieee.org/groups/1149/1/index.html)。本例用于学习这一机制，真实器件还需按照其边界单元、指令及电气规则安排测试。
