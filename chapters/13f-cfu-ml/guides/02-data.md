# 2. 四个小整数怎样装进CPU的两个寄存器？

先打开[main.c](../main.c)中的pack_inputs、pack_weights，再看上游[cfu_mac.v](../upstream/cfu_mac.v)的四个prod。

## 2.1 为什么需要打包？

CFU接口每次接收两个32位操作数，但我们想同时算四对8位数。因此每个寄存器拆成四个小格子，叫四个lane：

```text
32位操作数
┌──────────┬──────────┬──────────┬──────────┐
│ [31:24]  │ [23:16]  │ [15:8]   │ [7:0]    │
│ lane3    │ lane2    │ lane1    │ lane0    │
└──────────┴──────────┴──────────┴──────────┘
高位                                       低位
```

CPU不是把四个数组地址交给CFU，而是先读出四个数，再将它们组合为一个值。当前CFU不知道数组位于哪个RAM地址。

## 2.2 先理解有符号8位的位表示

同样的8位模式，在不同解释下有不同数值：

| 位模式 | 无符号解释 | 有符号二补码解释 |
| --- | ---: | ---: |
| 0x01 | 1 | 1 |
| 0x7f | 127 | 127 |
| 0x80 | 128 | -128 |
| 0x81 | 129 | -127 |
| 0xff | 255 | -1 |

位本身没有“正负标签”，C的int8_t和Verilog的$signed决定怎样解释它。对有符号8位数，最高位为1时，数值可以用“无符号值减256”理解。

## 2.3 为什么输入1要变成0x81？

原版核心明确写了：

```verilog
localparam InputOffset = $signed(9'd128);
```

乘法前又写：

```verilog
$signed(cmd_payload_inputs_0[7:0]) + InputOffset
```

所以硬件真正使用的输入值为“有符号字节值+128”。为了让最终参与乘法的数仍然是输入x，软件必须传入q=x-128：

```text
想算的输入x=1
  → 软件先算q=1-128=-127
  → -127的8位模式为0x81
  → 硬件把0x81解释为-127，再加128
  → 恢复为1，才与权重相乘
```

如果直接传0x01，硬件会按1+128=129计算，结果就错了。这不是神经网络都要求加128，而是这个现成核心的固定数据约定。

## 2.4 完整的13案例怎样打包？

```text
原始输入x：     1       2       3       4
传入有符号q： -127    -126    -125    -124
字节模式：     81      82      83      84
权重w：        2      -1       3       1
字节模式：     02      ff      03      01
```

规定第一个元素放最低8位：

```text
input0 = 0x84_83_82_81
             │  │  │  └─lane0
             │  │  └────lane1
             │  └───────lane2
             └──────────lane3

input1 = 0x01_03_ff_02
```

硬件看到四路：

```text
lane0：(-127+128) ×  2 =  2
lane1：(-126+128) × -1 = -2
lane2：(-125+128) ×  3 =  9
lane3：(-124+128) ×  1 =  4
累加：13
```

## 2.5 pack_inputs逐行看

```c
uint32_t word=0;
```

先建立一个全0的32位容器。

```c
for(unsigned lane=0;lane<4;lane++) {
```

逐个填四个8位格子。这个4来自所选核心的四路结构。

```c
int value=lane<n ? x[lane] : 0;
```

若这一组还有有效元素，就取该元素；不足四项的位置补数学意义的输入0。n在这里是本组有效元素数，而不是整个数组长度。

```c
word|=(uint32_t)(uint8_t)(value-128)<<(8*lane);
```

从内到外拆开：

1. value-128：匹配核心的输入约定。
2. 转uint8_t：保留该数的低8位模式。例如-127得到0x81。
3. 转uint32_t：把位模式放入无符号32位数，避免用负数左移。
4. 左移8×lane：lane0移0位，lane1移8位，依次放到对应格子。
5. `|=`：将这个格子的位合并进去；各格子不重叠。

```c
return word;
```

返回打包值。不是返回指针，也不是告诉CFU从这里开始读四个字节。

## 2.6 pack_weights的不同之处

权重不做-128转换，只保留int8_t的位模式，移入对应lane。例如-1先转uint8_t得到0xff，再扩成uint32_t后左移。

不足四项的位置补权重0；这个lane的乘积就是0，不应改变结果。

## 2.7 三个元素的尾部怎么办？

如果n=3：

```text
有效：lane0、lane1、lane2
补齐：lane3的数学输入为0、权重为0

补齐输入的编码是0x80：有符号-128，加128后才是0。
```

直接把整个input0初始化成0，再不写剩余lane，在本核心中会让该lane的输入被解释成128。当前权重也补0时乘积仍是0，但最好把输入编码也定义正确，避免换权重或复用数据后暴露错误。

打包使用显式移位，因此不依赖把uint8_t指针强转成uint32_t指针；不要求数组按4字节对齐，也不依赖主机内存端序猜lane顺序。
