# 课堂回顾答案与达标点

1. **点积与神经元：** 每个输入乘自己的权重，再相加；加bias、激活后形成一个输出。达标：能手算13，指出bias/ReLU本章仍由CPU执行。
2. **输入编码：** 该核心按有符号字节加128后计算，输入1应先编码为-127，即0x81。达标：能解释直接传0x01会变成129，知道128不是所有网络统一规则。
3. **四个lane：** 一个32位操作数装四个8位数；硬件按四段切片计算。改16位要重新设计lane数、切片、乘积/累加位宽、打包与参考，不能只把C类型改掉。
4. **功能号：** funct7=0累加，非零funct7清零；本章使用1清零。低三位funct3被这个核心忽略。达标：不会把清零当作自动发生，也不会把其他funct7解释成尚未实现的功能。
5. **背压：** rsp_ready=0表示结果尚未被接收；必须保留valid和结果，不能重复执行旧命令。达标：会用沿之前valid&ready判断一次接受。
6. **CPU插件：** CUSTOM0只是预留编码空间，需要CPU译码和CFU插件端口配合。普通CPU不会因为接上一份文件就自动支持；当前LiteX要求cpu_variant与cpu_cfu一起提供。
7. **实际硬件使用：** 看反汇编CUSTOM0和真实cmd_valid&cmd_ready计数。硬件模式有5个静态指令位置、动态619次接受；软件模式两者均0。结果相同只能证明某些计算一致，不能单独证明用了硬件。
8. **计时范围：** 逐次打包版增加读取、移位和函数开销；预打包版把这部分放到计时之前，只看操作数就绪后的内核。达标：能同时报告两种成本，不能将727周期说成整个网络推理耗时。

再检查自己能否沿着以下路径解释一次计算：

```text
main.c中的四个元素
 → pack_inputs/weights形成两个32位值
 → cfu_op0宏生成CUSTOM0
 → VexRiscv读取源寄存器、发出命令
 → Cfu切片、符号解释、乘加并保存响应
 → CPU接收结果写回目标寄存器
 → C程序比较，TRACE通过Wishbone报告
```

若能逐段说清“这里是数据、地址、寄存器编号还是硬件连线”，就掌握了本章最重要的内容。
