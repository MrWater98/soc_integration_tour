# 当前告警、未覆盖和未完成项

这份文件区分“已经理解的生成代码告警”和“仍需补证据的验证项目”。不以仿真PASS自动豁免所有告警。

## lint告警的逐类判断

实际数量在results/20/summary.json的lint_warning_counts中，原始位置在lint.log。

| 类别 | 位置与解释 | 当前处理 |
| --- | --- | --- |
| WIDTHEXPAND | 本地GPIO 4位、pending 1位、stage 8位读到32位总线 | 无符号零扩展符合寄存器定义；检查高位应为0 |
| WIDTHEXPAND | UART_DIV参数由Migen按当前值最小位宽传入，装入16位tx_div | 当前DIV=8，DIV-1=7可表示；改变分频值须重新检查范围和帧周期 |
| WIDTHEXPAND | LiteX地址比较常量使用较短位宽，或1位IRQ接32位向量 | 零扩展，IRQ位0有效，其余为0；译码与IRQ实际功能已回归 |
| WIDTHTRUNC | CPU字节地址右移2后输出30位Wishbone adr | 去掉原32位地址中右移后为0的最高两位，不丢有效地址 |
| WIDTHTRUNC | CPU移位器33位中间量写32位结果 | 预生成CPU的32位结果截取；仅对当前CPU版本记录，不宣称已完整验证所有移位指令 |
| WIDTHTRUNC | LiteX Wishbone到CSR桥保留低位地址 | CSR窗口内部使用局部地址，外层已有区域译码；本章无业务CSR |
| CASEINCOMPLETE | LiteX CSR桥FSM生成case缺少所有编码的显式分支 | 组合过程有默认值避免锁存，复位状态有效；没有形式证明非法状态自恢复，生产阶段仍需审查 |

脚本拒绝LATCH/MULTIDRIVEN/UNOPTFLAT。其余新告警不能只加-Wno参数掩盖，需检查新来源并更新本表。这里保留CPU源文件和生成器原样，没有为“让报告变绿”改写第三方逻辑。

## 覆盖率里的未命中行

coverage.info和annotated目录来自一次正常启动。未命中项按以下原则处理：

- CPU未执行的指令译码、异常、中断分支：待补定向程序；没有直接豁免。
- 软件错误码分支：本章在Icarus故障回归中有部分执行，但尚未合并进Verilator覆盖数据库；不能在这份统计中虚报命中。
- CSR桥无业务访问路径：当前接口范围排除业务功能，但译码、非法访问和总线超时仍需进一步验证。
- Timer/GPIO/UART的边界状态：正常固件和随机模型覆盖一部分；UART忙写、所有分频参数、所有复位帧位置仍未穷举。

本次不将所有未命中项逐行自动标成不可达。报告保留原始行号和命中数，生产冻结前必须逐项补测或提供不可达证明。

## CDC/RDC和时序

当前只有单一sys工作时钟；GPIO双触发器、reset_sync双触发器通过结构阅读和功能试验。没有专用CDC/RDC报告，没有模拟亚稳概率计算，没有布局后同步器距离、recovery/removal、多角STA。因此这些项目保留OPEN。

## 形式检查的范围

只证明外设在初始复位假设下12步内的几个安全属性。没有对任意长时间、所有CPU指令或完整SoC做形式证明，也没有完整顺序等价。

## 什么时候可以删掉OPEN？

必须补上对应工具、输入版本、可执行检查和结果，不能因为后面章节又得到一个PASS就批量删掉。本章summary的状态写明production freeze OPEN。
