# 13E：完整 SoC 的仿真工具对照

## 结论

在本机对同一份第 13 章 SoC 和同一正常场景进行测量，Verilator 中位运行时间为 0.166 s，VCS 为 1.418 s，Xcelium 为 1.821 s。也就是说，这次测试中开源 Verilator 的运行阶段约快 8.5 倍和 11.0 倍。商业工具编译更快：VCS 为 2.72 s、Xcelium 为 1.47 s，Verilator 约 6.1–6.5 s。结果适用于本次主机、版本、场景和设置，不应外推为普遍排名。

仓库提交了 `results/13e/summary.json` 与 `results/13e-xrun/summary.json`，阅读结论不需要安装商业仿真器。运行器在本机结果目录另外保存原始日志和构建文件，这些体积较大的文件不纳入版本库。要在其他机器复现，只需运行环境中可用的工具；缺失工具会标记为 `SKIP`，不会影响查看已记录的结论。

本附录复用第 13 章的完整 `sim.v`、VexRiscv RTL、外设模型和 ROM 初始化文件。同一个 `bench13e.sv` 只提供 100 MHz 时钟与超时保护；SoC 写入完成端点时自行结束仿真。两端都关闭波形和覆盖率插桩，分别测量编译时间与三次单场景运行时间。运行器保存输入哈希、工具版本、原始日志与墙钟时间，并核对八项串口自检、完成码和模拟时钟数。

## 运行

先运行第 13 章生成 `results/13/rtl/`，然后在本机执行：

```bash
module load lic/eda vcs/2023.12 gcc/gcc-12.2.0
python chapters/13e-tool-comparison/run.py
```

`--commercial xrun` 可改用 Xcelium；建议同时指定 `--output results/13e-xrun`，保留 VCS 原结果。`--runs N` 控制重复次数。加载商业工具只影响可执行程序与许可证环境，不改变 HDL。Verilator 的 C++ 编译需要较新的 GCC；本机默认 GCC 4.8.5 无法接受当前 Verilator 的编译参数。本机 Xcelium 模块的默认 `xrun` 入口为 32 位程序，脚本会选择同安装目录的 64 位入口。

## 本机结果（2026-10-10）

输入是 `results/13/rtl/sources.json` 中第 13 章快照，运行主机 `vm_yangdilyu`。完整版本、SHA-256、编译命令和三次原始时间见 `results/13e/summary.json`、`results/13e-xrun/summary.json`；编译/运行日志在各自结果目录。Xcelium 使用第二次独立批次中的 Verilator 测量。本次无 FST、代码覆盖或图形界面。

| 工具 | 编译墙钟 | 三次运行墙钟 | 中位运行墙钟 | 八项自检/完成码 | `SIM_CYCLES` |
| --- | ---: | --- | ---: | --- | ---: |
| Verilator 5.029 devel | 6.13 s | 0.216、0.167、0.166 s | 0.167 s | PASS | 145997 |
| VCS V-2023.12 | 2.72 s | 1.518、1.418、1.368 s | 1.418 s | PASS | 145996 |
| Verilator 5.029 devel（Xcelium 批次） | 6.53 s | 0.166、0.164、0.165 s | 0.165 s | PASS | 145997 |
| Xcelium 23.09-s004 | 1.47 s | 3.021、1.821、1.770 s | 1.821 s | PASS | 145996 |

本次 VCS 的中位运行墙钟约为同批 Verilator 的 **8.5 倍**，Xcelium 约为同批 Verilator 的 **11.0 倍**。编译时间只测了一次，不能用来给工具作普遍排名。三端固件输出与完成码一致，但商业事件仿真器的 `final` 时钟计数比 Verilator 少一拍，结束时 `bus_monitor` 记录的 SRAM 事务数也相差一笔（20 与 21）。因此此结果证明了本场景输出检查通过，不代表逐拍完全一致；更强的等价结论需比较事务序列或波形。

Verilator 将 RTL 编译成 C++ 可执行程序；VCS 在这里运行的是事件仿真器。运行时间与编译时间应分开看：大量重复回归可摊销一次编译成本，而只跑一次时还要计入编译。商业工具的价值还包括多语言测试台、调试与覆盖功能等，但这些能力没有在本实验中打开，不能从此表推断它们的效果。许可证排队、共享主机负载、线程设置和波形/覆盖开关也会改变数字。

如果任一工具缺失，摘要记 `SKIP`；编译或运行失败记 `FAIL`，不计算性能倍数。第 13 章原有八场景回归仍是功能验收基线，本附录目前只测正常自检。
